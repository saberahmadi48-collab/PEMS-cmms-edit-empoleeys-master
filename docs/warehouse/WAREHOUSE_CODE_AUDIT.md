# Warehouse Code Audit and Remediation Plan

Scope: stock posting, incoming receipts (IRN), store requisitions, reservations, work-order material sourcing, and the procurement queue. Findings are based on source inspection. Effects that depend on concurrency, deployed configuration, or data require QA confirmation.

| ID / priority | Evidence and impact | Action and acceptance criteria |
| --- | --- | --- |
| WH-01 / High | [Warehouse intake service](../../PEMS.Persistence/Servises/WarehouseIntakeService.cs#L139) calculates and validates the remaining quantity before opening the transaction that creates the requisition. It does not reread the balance inside that transaction. Concurrent operations could accept quantities against the same remaining demand. | Validate and record coverage under a common concurrency control. A relational-database test with two independent sessions must show that total coverage stays within demand and retries create no duplicate requisition. |
| WH-02 / High | [Material item controller](../../PEMS.Web/Areas/Warehouse/Controllers/MaterialItemController.cs#L145) uses the material-item creation permission for direct receipt and calls the stock service directly. The IRN path has disposition and approval controls. The business must define the permitted use of direct receipt and distinguish master-data permissions from stock receipt permissions. | Separate stock entry by receipt type and authorized role. Verify source-document matching and QC approval for standard receipts. Record a dedicated permission, reason, and audit history for opening balances or exceptions. |
| WH-03 / High | The [intake controller](../../PEMS.Web/Areas/Warehouse/Controllers/WarehouseIntakeController.cs#L33) checks module-level requisition view permission. The [sourcing service](../../PEMS.Persistence/Servises/WarehouseIntakeService.cs#L131) checks create permission and an active warehouse. An explicit warehouse assignment check and an open-task requirement were not found in this path. Impact depends on organizational policy. | Approve a role × warehouse × task-state matrix and enforce it at the service boundary. Test both in-scope and out-of-scope access with QA accounts. |
| WH-04 / Medium | [Coverage calculation](../../PEMS.Persistence/Servises/WarehouseIntakeService.cs#L104) includes drafts and excludes rejected or cancelled requisitions. The workflow can complete when the last draft is created. Automatic reopening after rejection, cancellation, or a short close was not established in this path. | Display requisition coverage, reservation, and physical issue separately. After rejection, cancellation, or short close, the remaining demand must be visible and eligible for reassignment where business rules allow. |
| WH-05 / Medium | [WorkOrderController](../../PEMS.Web/Controllers/WorkOrderController.cs#L682) calls the purchase and stock branches separately. A success in one branch can hide the other branch's error in the final message. | Display and record the outcome of each branch. Test partial success and retry to verify that the successful branch does not create duplicate records. |
| WH-06 / Medium | [Reservation release](../../PEMS.Persistence/Servises/StoreRequisitionLifecycleService.cs#L409) floors the resulting reserved balance at zero. If the stored balance is below the release amount, the calculation itself does not report the difference. Actual data was not checked for this discrepancy. | Measure discrepancies with a read-only reconciliation report. Define whether to block, refer for reconciliation, or perform a controlled correction. Test that discrepancies leave an audit record. |
| WH-07 / Medium | [Material item controller](../../PEMS.Web/Areas/Warehouse/Controllers/MaterialItemController.cs#L156) and the [requisition lifecycle service](../../PEMS.Persistence/Servises/StoreRequisitionLifecycleService.cs#L144) contain fixed-language messages. Persian messages can therefore appear on English pages. | Use Persian and English resources for operation results and verify errors, success messages, and messages with quantity arguments in both languages. |

## Follow-up sequence

1. Start WH-01 and WH-06 with read-only quantity reconciliation and relational-database tests. Preserve the requisition lifecycle's existing idempotency controls.
2. For WH-02 and WH-03, have Warehouse and QA define exception receipt policies, access scope, and operations permitted outside the queue.
3. Verify WH-04 and WH-05 in an end-to-end work-order scenario with partial issue and direct purchase, using independent acceptance checks for each branch.
4. Complete WH-07 by checking warehouse forms and messages in Chrome.
